# 多屏支持

Status: ready-for-human

## 问题

MonitorBar 现在只管理一台显示器：`display.Target()` 永远只返回一台（优先外接、否则内屏），`store` 是一台显示器的状态机，`settings.json` 扁平一份。接上两台以上外接显示器时，只有其中一台能被管理，其余无法调节，且没有界面提示它们的存在。

本 spec 让 MonitorBar 同时管理所有外接显示器：在面板里切换目标显示器，每台拥有独立的亮度、色温、场景、DDC 画面控制、输入源、音量、分辨率与自动切换设置。

术语见 [CONTEXT.md](../../CONTEXT.md)。

## 目标

- 所有外接显示器都被发现、被列出、可被选为目标。
- 每台显示器的设置独立，跨启动、跨重插保留。
- 现有单显示器用户的界面与行为不变（除去切换器）。
- macOS 与 Windows 同步交付。

## 非目标

- 批量操作（"应用到全部"）。
- 管理内屏（内屏只在没有外接时作为目标，并继续作为「跟随内屏」的来源）。
- 显示器重命名。
- 托盘右键菜单列出显示器。
- 每台显示器一组全局快捷键。
- 屏幕时间按显示器分别统计。

## 显示器发现与身份

每次显示器配置变化（`mygo.Screen.OnDisplaysChanged`）与系统唤醒时重新枚举外接显示器。枚举由 `internal/display` 自己完成，不使用 `mygo.Screen.Displays()`：后者的 `Display.ID` 是平台句柄，没有跨启动稳定性。

**显示器身份**是设置持久化的键：

- 主键：EDID 的厂商号 / 型号号 / 序列号。
- 主键重复时（同型号、序列号为 0，或多台同型号同时在线）追加位置键：macOS 用 `CGDisplayCreateUUIDFromDisplayID`，Windows 用 `DISPLAYCONFIG_TARGET_DEVICE_NAME.monitorDevicePath`。
- 查找顺序：精确身份 → 主键唯一匹配 → 视为新显示器。

**排序**：与系统「显示器」设置一致，主显示器在前，其余按屏幕坐标从左到右。切换器与"第一台外接"都用这个顺序。

**范围**：只列出外接显示器。镜像集里的副本与虚拟显示器（DisplayLink、远程桌面）不进入列表。

## 目标显示器

`target` 是当前操作的那台外接显示器，同一时刻只有一个。

- 启动与重插后：选上次选中的那台（按身份）；它不在线时选系统排列中的第一台外接。
- 目标离线：立即回退，不进入"无目标"状态。
- 没有外接显示器时：内屏作为唯一目标（与 1.11.1 相同），切换器不出现。

## 面板

- 切换器在 header 的显示器名称处：下拉，每项显示「名称 · 接口」。只有一台外接时退化为纯文字，不显示箭头。
- 四个分页统一读目标显示器；切换目标后当前分页保持。
- footer 显示目标那台的通道状态。单台时保持 1.11.1 的规则（没有通道就什么都不说）；多台时需要能看出"这台没有硬件通道"，用"仅软件调光"之类的文案说明。
- HUD 多台时带显示器名称，例如「REDMI · HDMI1　亮度 60」。

## 每台显示器的状态

按显示器：亮度（硬件与软件）、色温、场景、DDC 画面控制、输入源、音量与静音、分辨率与刷新率、跟随内屏的开关与范围、日夜自动切换的开关与日夜场景、局域网遥控的配对。

全局：语言、开机自启、HUD 开关、媒体键接管、快捷键键位、更新、日夜自动切换的时间表。

## 通道

三条通道都按显示器独立建立。

**探测时机**：目标显示器立即探测（模式、DDC、局域网可用性），其余显示器后台串行探测，不阻塞面板打开；切换器里把它们标为「检测中」。

**DDC/CI**：

- Windows 已按 `HMONITOR` 匹配物理显示器，接上身份即可。
- macOS Apple Silicon 必须把 `DCPAVServiceProxy` 与具体显示器对上（见 [ADR-0002](../../docs/adr/0002-apple-silicon-ddc-binding.md)）。
- 绑定失败或无法区分时，该台标记为"硬件控制不可用"，退回软件调光与深浅度调节，不做贪心配对；界面按上面的 footer 规则说明。

**局域网遥控**：

- 发现改为返回所有响应设备（地址 + 设备名 + 输入源），不再找到一个就停。
- 配对：显示器名称与设备名称唯一匹配时自动绑定；冲突（同型号、同名）时在「概览」页出现一张配对卡片，列出网络上未被占用的设备供选择。配对按身份记住，下次启动复用。
- 未配对的显示器照常使用 DDC 与软件通道。

**软件调光与色温**：按显示器各自捕获 Gamma 基线、各自恢复；退出时逐台恢复（macOS 还要调用 ColorSync 恢复）。

## 快捷键与媒体键

- 快捷键注册仍是一份全局键位；执行时作用于当前目标显示器。
- 输入源快捷键录制的是目标显示器的输入源；目标没有该输入源时不动作。
- macOS 接管键盘后：亮度键作用于目标显示器；音量键作用于**声音实际输出**的那台，与目标不一致时仍然调它（HUD 显示名称）。
- 快捷键列表显示的是目标显示器的输入源。

## 日夜自动切换

- 时间表全局（一份白天/夜晚开始时间）。
- 每台显示器有自己的开关与日夜场景；到点后各自切换，各自记住"上次应用的时段"，手动调整保留到下一次交替。
- 显示器重新接入时，若其上次应用的时段与当前时段不符，立即补齐。

## 屏幕时间

保持整机口径：**任一台被管理的显示器亮着就计时**（没有外接时为内屏）。活跃时长仍按全局键鼠空闲判断。`usage.json` 格式与历史数据不变。

## 设置与迁移

`settings.json` 升到 v2：

- 顶层保留全局项（语言、开机自启、HUD、媒体键、快捷键键位、日夜时间表）。
- `monitors` 按身份保存每台的状态。
- `selected` 保存上次选中的身份。

迁移：升级后第一次识别到外接显示器时，把 v1 的扁平静态（亮度、色温、网络地址、跟随范围）写进那台显示器的记录；升级后一直没有外接则保留 v1 字段，等第一台外接出现再迁移。拔掉的显示器记录永久保留，不自动清理。

## 命令行

`--probe` 逐台打印：名称、接口、身份、当前模式、原生分辨率、DDC 读数与能力、局域网发现结果与配对情况。

## 平台差异

- macOS：DDC 绑定依赖私有 API（ADR-0002）；位置键用 `CGDisplayCreateUUIDFromDisplayID`。
- Windows：位置键用 `monitorDevicePath`；DDC 走 dxva2，已是按显示器。
- 两端共同：`SleepNow`（关闭所有显示器）与 `IdleSeconds`（键鼠空闲）保持全局。

## 验收标准

1. 两台外接（一台有 DDC、一台没有）：切换器列出两台，亮度/色温/场景各自独立，重启后恢复。
2. 两台完全同型号、序列号都是 0：切换器用「名称 · 接口」区分；DDC 不能可靠配对的那台显示"仅软件调光"，另一台硬件控制正常。
3. 拔掉目标显示器：立即回退到第一台外接；插回后恢复它自己的设置与选中状态。
4. 只有一台外接：界面与 1.11.1 一致，切换器不出现。
5. 两台澎湃 OS 显示器、名称不同：自动配对；名称相同：出现配对卡片，手动选择后重启仍保持。
6. 目标从 A 切到 B 后，亮度快捷键调 B；声音输出在 A、目标为 B 时，音量键调 A。
7. 两台都打开日夜自动切换：各自到点切换；各自的手动调整保留到下次交替。
8. 屏幕时间：任意外接亮即计时；运行中拔掉一台不中断统计。
9. 从 1.11.1 升级：亮度、色温、网络地址落到第一台外接上。
10. `--probe` 列出所有外接显示器。
11. 三台外接时，面板在 1 秒内打开并可用（目标已探测），其余显示「检测中」。
12. 内屏跟随：多台外接时，各自跟随且各自范围设置生效。

## 风险

- **Apple Silicon 多外接 DDC 未实测**：配对方案在单外接机器上验证过，双外接的手工验收见 [issue 09](issues/09-hardware-verification.md)。
- **同型号显示器**：EDID 完全相同时只能靠位置键区分；位置键在换接口后会变，那台的历史设置将无法匹配（接受，写进 README 的已知限制）。
- **私有 API**：`IOAVServiceCopyEDID`、`CoreDisplay_*` 未文档化，需 dlsym 并在失败时降级。
- **串行探测**：多台时 DDC 很慢，必须后台串行，否则打开面板卡顿。
