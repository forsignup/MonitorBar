# 06 局域网全量发现与配对

Status: ready-for-agent
Blocked by: 03

## 背景

`mitv.Discover()`（[discover.go:43](../../../internal/mitv/discover.go#L43)）找到一个就返回，`store.connect`（[store.go:300](../../../store.go#L300)）只维护一个 `link` 与 `prefs.NetworkHost`。两台澎湃 OS 显示器时，先发现的那台会占掉唯一的连接。配对规则见 [spec](../spec.md#通道)。

## 要做

1. 新增 `mitv.DiscoverAll() ([]Device, error)`：扫描各私有 /24，收集**所有**通过 `IsMonitor()` 的设备（地址、设备名、输入源）。保留 `Discover()` 作为兼容薄封装。
2. 配对表存进 v2 设置（按显示器身份 → 设备地址），并在每次探测时校验：设备仍在线、仍是显示器。
3. 自动配对：显示器名称与设备名称归一化（大小写、空白、全半角）后唯一匹配且该设备未被占用时自动绑定。
4. 手动配对：「概览」页在目标未配对、且网络上有未被占用的设备时出现一张卡片，列出设备供选择；选择后立即绑定并持久化。文案进 locales。
5. 探测策略沿用 03 的队列：目标先扫，其余后台；同一时刻只有一个扫描在跑。

## 验收

- 两台 HyperOS、名称不同：都自动配对，重启后保持。
- 两台同名：都不自动配对，卡片可选；选完重启仍保持。
- 一台 HyperOS + 一台无网络通道：只有前者出现局域网输入源与音量，后者退回 DDC/软件。
- 显示器拔掉再插回：配对仍在，不重新扫描就能恢复。
- 单测覆盖名称归一化与"设备已被占用"的分支（纯函数，不发网络请求）。

## 备注

`IsMonitor()` 会各自发请求，全量扫描时注意并发上限，别把 /24 扫成雪崩（沿用现在的 goroutine 池规模即可）。设备名可能被用户改名，因此自动配对失败不是错误，只是需要手动。
