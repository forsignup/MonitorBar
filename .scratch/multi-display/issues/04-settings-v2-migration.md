# 04 设置 v2 与迁移

Status: ready-for-agent
Blocked by: 01, 03

## 背景

`settings`（[settings.go:10](../../../settings.go#L10)）是一份扁平静态：`SoftBrightness`、`Warmth`、`NetworkHost`、`FollowMin/Max` 都属于"那唯一一台显示器"。多屏后要按身份存，全局项留在顶层。迁移规则见 [spec](../spec.md#设置与迁移)。

## 要做

1. 定义 v2 结构：
   - 顶层全局：语言、开机自启、HUD、媒体键接管、快捷键键位、日夜时间表。
   - `monitors`: `map[identity]monitorPrefs`，包含亮度、色温、网络地址、跟随内屏开关与范围、日夜开关与日夜场景、上次应用的时段。
   - `selected`: 上次选中的身份。
2. 迁移：读到的 v1 文件在**第一次识别到外接显示器**时写入该显示器的记录，并标记已迁移；升级后一直没有外接则保留 v1 字段，等第一台外接出现再迁移。迁移只做一次，字段读不到时用现有默认值。
3. 面板与动作读写 v2；`settings.save` 保持"只在 dirty 时写"。
4. 提供测试用的最小 fixture（v1 完整、v1 缺字段、v1 含旧场景中文名），覆盖迁移的一次性与幂等。

## 验收

- v1 文件升级后：亮度、色温、网络地址落到第一台外接，其余显示器取默认值。
- 第二次启动不会重复迁移，也不会覆盖用户在 2.0 里的改动。
- 没有任何外接时升级：文件保持可读，第一台外接出现时再迁移。
- 拔掉的显示器记录仍在文件里；重新接入能读回。

## 备注

不要为"已迁移"单独加一个布尔值以外的东西——版本号或 `migrated` 字段都可以，但要让 1.11.1 回退后仍能读出全局项（顶层字段保持原名）。
